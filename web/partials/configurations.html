Full history ({history})

The full per-round transcript is always injected via the {history} placeholder for every round after the first. Agents have episodic memory inside a Run — they can read every choice made so far, by every agent, in order. There's nothing to toggle here; it's part of the engine.

Rolling reputation window

When set, the placeholders {coopRateN} / {reputationN} average each opponent's behaviour over the last N rounds only. Leave 0 to use the full history.

Turn off for asymmetric coordination games (Battle of the Sexes), zero-sum games, or any setup where strategy1 doesn't mean "cooperate". When off, the reputation placeholders fill with n/a regardless of history.

Memory across runs — roadmap

Within one Run, agents see every past round through {history}. Across separate Runs (different iterations or different Configurations) there is no persistence today: every Run is a fresh start. Memory across runs (online-learning / no-regret dynamics) is a planned engine extension; for now use seed control + iterations to get reproducible replicates.

Second-order belief elicitation (active)

With elicit beliefs ON and theory-of-mind depth ≥ 2 the engine also asks each agent "what does your opponent think YOU will do?" every round, and scores the answer against the opponent's actual first-order belief from the same round (soft-target Brier). The template must carry a {believe2}: […] block — without it the phase is skipped.

Surfaces in results as agentN_belief_2nd_order_per_round_brier / agentN_belief_2nd_order_mean_brier.

Per-agent opponent-prior probability

This is what each agent is told about its opponents. If you set agent1's value to 0.7 and agent2's personality is "cooperative", agent1's prompt will read "agent2 has a 70% probability of being cooperative".

  • 0 — agent is told nothing about the opponent (the entire {opponentIntro} block is stripped).
  • 0<p<1 — agent is told the opponent has personality X with probability p × 100%.
  • 1 — common knowledge: agent is told the personality is certain.

Drives the {opponentPersonalityProbability1} placeholder in the prompt. Setting all opponents to 0 has the same effect as tomOrder = 0: the agent gets no opponent intro at all.

Time-discounting and risk / inequity preferences can act as a behavioural treatment (written into the prompt), an analysis lens (applied only to the score), or both. The badge on each shows where it currently acts. Setting it to "both" double-counts the same preference, so prefer one channel unless you mean to.

δ < 1 means future rounds matter less. 1.0 = no discount.

"Prompt" makes δ a behavioural treatment on the LLM's choices and skips the score-side discount, so the same preference isn't counted twice.

"Prompt" turns CRRA into a behavioural treatment: the agent is told it is risk-averse and the score is left untransformed. Prompt-side framing is only available for CRRA; Fehr-Schmidt always applies to the score.
