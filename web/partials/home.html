Guide

A long-form version of this guide is in docs/USER_GUIDE.md. Below is the in-app summary — open the sections in order on your first read.

1. Purpose

FAIRGAME is a virtual laboratory for studying how Large Language Model (LLM) agents behave in classical game-theory scenarios. You set up a 2-or-more-agent game, fill in the rules and personalities, run it on real or simulated agents, and read out a structured table of choices, scores, beliefs and welfare metrics.

It was built to answer empirical questions like:

  • Do LLM agents cooperate, or do they exploit each other?
  • Does the answer change when the prompt is in French vs English?
  • Does a stronger model outsmart a weaker one in a one-shot Prisoner's Dilemma?
  • Does explicit Theory-of-Mind reasoning shift behaviour?
  • What happens with a covert "fake-message" channel between agents?

The framework has three layers:

Template            Configuration        Run
(prompt body)       (template + params)  (engine output)
   game → variant      template + params  run id + rows
   per language       cfg                  CSV + metadata

You write a Template per game per language. You build a Configuration that points at (game, variant, languages) and bundles every engine setting. You run it as many times as you like; each run lands on the Results page with charts.

2. Templates

A Template is the prompt body the agent sees, with placeholders the engine substitutes at run time. The Templates page lets you manage them as a library: 

Game: "Prisoner's Dilemma"
 ├── Variant: "classic"
 │    ├── language: en  →  body...
 │    ├── language: fr  →  body... (auto-translated via the AI button)
 │    └── language: cn  →  body...
 └── Variant: "with-communication"
      └── language: en  →  body...

Plain placeholders {name}

Placeholder Meaning
{currentPlayerName}The agent's own name
{personality}The agent's personality (per language)
{opponent1}, …Each opponent's name
{opponentPersonality1}, {opponentPersonalityProbability1}Stated personality of opponent and the % probability it's actually that way
{strategy1}, {strategy2}Display labels for strategies (from the payoff matrix)
{weight1}..{weight4}Numeric payoffs from the matrix
{nRounds}, {currentRound}Game length and current round number
{history}Engine-rendered text describing past rounds
{coopRate1}, {reputation1}, …Rolling cooperation rate and label of each opponent
{ownType}, {typeDistribution}Bayesian-game private type / public prior

Conditional blocks {name}: [...]

  • {intro}: […] — always kept (use it for the agent's identity).
  • {opponentIntro}: […] — kept when tomOrder ≥ 1; stripped at order 0.
  • {gameLength}: […] — kept only when nRoundsIsKnown: true.
  • {communicate}: […], {choose}: […], {believe}: […], {believe2}: […], {mixedChoose}: […] — phase-specific blocks; only the active phase survives.
  • {believe2}: […] fires only when elicitBeliefs: true AND tomOrder ≥ 2. The agent predicts what its opponent thinks IT will do — the output is a JSON distribution over the agent's own strategies. Without the block in the template the phase is silently skipped.
  • {secondOrder}: […] — kept when tomOrder ≥ 2.
  • {ownType}: […] — kept when the agent has a private type.

The 🌍 Translate button on a template fans out into target languages via the configured TemplateTranslator. The new entries are linked back to the source via source_template_id.

3. Configurations

A Configuration is the complete description of an experiment — everything the engine needs to run a set of games. Build it on the Configurations page using the tabbed form (General / Agents / Payoff matrix / Game theory / History / Beliefs / Reproducibility / JSON view).

Personality assignment modes

  • Per agent: positional — each agent has its own personality string.
  • Pool with permutations: define a personality pool on the Agents tab and a matching opponent-knowledge probability pool on the Beliefs tab; the engine generates one game per permutation across the agent slots (allAgentPermutations: true).

Communication styles

StyleEngine fields
Noneno inter-agent messages
RealagentsCommunicate: true
Fake (decimal)fakeCommunication: true, fakeMessageBase: dec
Fake (hex)fakeCommunication: true, fakeMessageBase: hex

Beliefs & Theory of Mind

  • elicitBeliefs — adds a per-round first-order belief phase; Brier score (one-hot target = realised opponent strategy) is computed afterwards.
  • tomOrder ∈ {0, 1, 2} — controls how much the agent is told about its opponent. Order 0 strips {opponentIntro}; order 2 keeps {secondOrder}.
  • Second-order beliefs (B1). When elicitBeliefs: true AND tomOrder ≥ 2, the engine also runs a believe2 phase asking each agent what its opponent thinks IT will do (distribution over the agent's own strategies). Scoring uses the opponent's actual first-order belief from the same round as the soft target. Result columns: agentN_belief_2nd_order_per_round_brier / agentN_belief_2nd_order_mean_brier. Requires a {believe2}: […] block in the template, otherwise the phase is silently skipped.
  • Per-agent opponent-knowledge probability (Beliefs tab) — what each agent is told about the opponent's personality. Pool mode replaces the per-agent values with a probability pool the engine permutes across slots.
  • reputationWindow — rolling cooperation-rate window (rounds). Lives on the History tab.
  • reputationApplies — turn off for Battle of the Sexes / zero-sum games where strategy1 doesn't mean "cooperate". Lives on the History tab.

Game-theoretic extensions

  • discountFactor, continuationProbability
  • equilibria (manual list or "auto" → nashpy)
  • paretoOptimalSum for welfare efficiency
  • mixedStrategies — agent emits a distribution; engine samples
  • Utility transform: Identity / CRRA(γ, offset) / Fehr-Schmidt(α, β)
  • baselineSemantics: {cooperate, defect} when mixing baselines into non-PD games

Reproducibility

  • seed — master seed; same seed → identical run.
  • seedCount — engine-side multi-seed averaging within a single run.
  • Experiments page Iterations per config — runs the configuration N times back-to-back, each as a separate Run.

Cloning & payoff variants

  • Clone a saved configuration to start from a copy and tweak any field (name suffixed with (copy); collisions auto-bump).
  • Payoff variants on the Matrix tab let one configuration carry multiple named matrices. On Save, the configuration becomes a group; the saved-list shows it as a tree with one child per variant, each runnable and named <config> · <variant>. Useful when only the payoff differs across runs.
  • The schema (variations: [{axis, name, value}]) is generic — payoff is just the first axis; future axes (rounds, ToM order, …) plug in without migration.
  • Save rejects name collisions across the whole library (409); rename and retry.
4. Fully-featured PD template (every placeholder + every block)

The classic shipped template uses about half of what the engine recognises. Below is a Prisoner's Dilemma template that exercises every placeholder and every conditional block. Use it as the ceiling — most real templates use a subset, but if you want to switch on Theory-of-Mind order 2 plus belief elicitation plus a real communication phase plus reputation labels plus private types, the prompt needs all of the corresponding markup or those features have nothing to fill. 

You are {currentPlayerName} and your opponent is {opponent1}.

{intro}: [
You are {personality}.
{ownType}: [Your private type is {ownType}; this fact is not visible to {opponent1}.]
]

{opponentIntro}: [
{opponent1} has a probability of {opponentPersonalityProbability1}% of being {opponentPersonality1}.
{opponent1}'s rolling cooperation rate over recent rounds is {coopRate1}, which we summarise as: {reputation1}.
The prior over types in this population is: {typeDistribution}.
]

{secondOrder}: [
Be aware: {opponent1} is also reasoning about you, knows that you are reasoning about them, and may try to anticipate your move.
]

You and {opponent1} are arrested for a crime and held in separate cells.

Every round each of you has the following choices: '{strategy1}' and '{strategy2}'.
{gameLength}: [There are {nRounds} rounds in total.]
The current round is number {currentRound}.

If you both choose {strategy1}, you both get a payoff of {weight1}.
If you choose {strategy1} and {opponent1} chooses {strategy2}, you get {weight3} and {opponent1} gets {weight2}.
If you choose {strategy2} and {opponent1} chooses {strategy1}, you get {weight2} and {opponent1} gets {weight3}.
If you both choose {strategy2}, you both get a payoff of {weight4}.

This is the history of the choices made so far: {history}.

{communicate}: [
Before choosing this round, send {opponent1} a short free-text message. They will see it before they choose.
Output ONLY the message text.
]

{choose}: [
Your goal is to maximise your payoff.
Choose between {strategy1} and {strategy2}.
Output ONLY the choice.
]

{mixedChoose}: [
Your goal is to maximise your expected payoff.
Output a JSON object that gives the probability you assign to each strategy, summing to 1.
Example: {"{strategy1}": 0.7, "{strategy2}": 0.3}
Output ONLY the JSON.
]

{believe}: [
Before you choose this round, predict what {opponent1} is about to do.
Output a JSON object with the probability you assign to each of their strategies, summing to 1.
Example: {"{strategy1}": 0.4, "{strategy2}": 0.6}
Output ONLY the JSON.
]

Section-by-section breakdown

Identity (always kept)

  • {currentPlayerName} — the agent's own name (agents.names[i]).
  • {opponent1}, {opponent2}, … — each other agent's name. Numbering is positional with respect to the active agent.
  • These are populated unconditionally; there is no toggle that hides them.

{intro}: […] block — always kept, but its inner text is conditional

  • Survives unless the agent's personality is the literal string "None" — in that case the engine strips the whole block.
  • {personality} is the agent's personality string in the active language. Comes from agents.personalities[lang][i]. Only available inside this block — a bare {personality} elsewhere will KeyError.
  • The nested {ownType}: […] block is kept only when the Configuration assigned a private type to this agent (agents.types); used in Bayesian-game studies. {ownType} is the realised type label.

{opponentIntro}: […] — Theory of Mind information

  • The whole block is stripped at tomOrder = 0. That's the entire point of order 0 — the agent gets no information about its opponent. At order 1 (default) and 2, the block survives.
  • It's also stripped if every opponent has opponentPersonalityProb = 0 or personality "None".
  • Per-opponent placeholders are numbered: {opponent2} / {opponentPersonality2} / {opponentPersonalityProbability2} / {coopRate2} / {reputation2}, etc.
  • {opponentPersonalityProbability1} is the probability the opponent truly has the stated personality, expressed in 0–100 (the engine multiplies the 0–1 input by 100 for readability).
  • {coopRate1} and {reputation1} come from history:
    • If reputationApplies = true and history exists, coopRate1 is the fraction (e.g. "0.62") and reputation1 is one of highly cooperative, moderately cooperative, occasionally cooperative, uncooperative.
    • If reputationWindow = N, only the last N rounds are averaged.
    • If reputationApplies = false (Battle of the Sexes, zero-sum) or there's no history yet, both render as n/a / unknown.
  • {typeDistribution} is filled when the Configuration sets typesAreCommonKnowledge = true and agents.types is set. Otherwise it'll appear literally — wrap it in another conditional if needed.

{secondOrder}: […] — only at tomOrder = 2

  • Kept iff tomOrder >= 2.
  • No new placeholders inside — compose recursive "they think we think" reasoning out of the standard opponent placeholders.

Cover story (plain text)

No conditionals; you control the framing here ("crime" → cooperative, "investment" → economic). The most studied source of bias in LLM PD prompts.

Strategies + horizon + round

  • {strategy1}, {strategy2}, {strategy3}… come from the payoff matrix's per-language label dict.
  • {gameLength}: […] survives only when nRoundsIsKnown: true. Lets you study uncertain-horizon behaviour without rewriting the body.
  • {currentRound} is per-round state, 1-indexed.

Payoff statement

  • The four {weightN} numbers come from payoffMatrix.weights. The body is reused across conventional / harsh / mild variants by changing only the weight values.
  • For 3+ strategies, reference {weight5}, {weight6}, … for additional weight keys.

{history} — engine-rendered

Free-text summary of past rounds; no template-side control over how it renders.

Phase blocks — exactly ONE survives per render

  • {communicate}: […] — runs only when agentsCommunicate: true. Output becomes the logged message.
  • {choose}: […] — strategy choice when mixedStrategies: false.
  • {mixedChoose}: […] — replaces choose when mixedStrategies: true; output is JSON probabilities.
  • {believe}: […] — runs only when elicitBeliefs: true; output is parsed into Brier-score input.
  • Include all blocks for every phase your Configuration might enable. If a block is missing and the phase fires, the engine sends an empty section — usually not what you want.

What's NOT yet in this template

  • More than 2 agents: copy the per-opponent block for opponent 2, 3, … Add the matching rows in the payoff statement.
  • More than 2 strategies: reference {strategy3}, {strategy4}, … in the payoff statement and phase blocks.
  • More than 4 weights: reference {weight5}, {weight6}, …
  • Stop conditions, continuation probability, discount factor — these don't inject any placeholder by default. If you want the agent to know about them, write the framing into prose yourself.
  • Tournament mode — same template; the engine spins up one game per pair.
  • Utility transforms (CRRA, Fehr-Schmidt) — applied numerically after the round; the agent sees raw payoffs in the prompt regardless. Add prose if you want this visible.

Edge cases / footguns

  • Bare conditional placeholder. A bare {ownType} outside the surrounding {ownType}: […] block raises KeyError when no type is configured. Always wrap conditional placeholders in their conditional block.
  • Missing phase block. If elicitBeliefs: true but the template has no {believe}: […] block, parsing will fail. Use the fully-featured template above as a safe default.
  • Bare {personality}. Only set when the surrounding {intro}: […] block is kept; bare references will KeyError.
  • First round. {coopRate1} is n/a on round 1. Phrase the surrounding sentence so it reads naturally even with n/a.
5. Glossary
  • Agent — one participant; LLM or a baseline strategy (TitForTat, GrimTrigger, …).
  • Strategy — what the agent picks each round.
  • Payoff matrix — points each agent earns per strategy combination; structure is {strategies, weights, combinations, matrix}.
  • Equilibrium — strategy combination where no agent regrets its move.
  • Theory of Mind — the agent reasoning about its opponent's choice; supports orders 0 / 1 / 2 plus belief elicitation.
  • Brier score — calibration metric for predictions (lower = better, 0 = perfect).
  • Discount factor (δ) — multiplies each round's payoff by δround-1.
  • Continuation probability — stochastic horizon: at end of each round, game continues with this probability.
  • CRRA / Fehr-Schmidt — utility transforms for risk aversion / inequity aversion.
  • Tournament — round-robin between every pair of agents.
  • Trust / monitoring — each round an agent first decides whether to LOOK (pay a cost to see the opponent's history) or NO_LOOK (act on trust). Surfaces as look_rate and monitoring_cost_total.
  • Mixed strategies — the agent outputs a probability distribution over strategies; the engine samples its move.
  • Welfare / regret — welfare = how good outcomes are collectively (sum, min, Gini, efficiency); regret = how much better an agent could have done against the same opponents.
  • Seed / Seed count / Iterations — pin random choices, engine-side multi-seed averaging within one run, vs. running the same config N times.
  • Game / Variant / Template — game family / parameter sub-family / per-language prompt body.
